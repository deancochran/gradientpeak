# Drizzle Baseline Mirror Guide

Use this file when working in `packages/db/drizzle`.

## Scope

- The generated MVP baseline mirror in `deploy/`.
- Drizzle configuration for relational schema inspection.
- No deployable history, forward chain, data-preservation, backfill, or upgrade mechanism.

## Rules

- Keep migration changes aligned with `packages/db/src/schema/**` ownership.
- `supabase/migrations/` has exactly one mutable pre-release MVP baseline authority; `deploy/` has exactly one generated byte-identical mirror.
- Edit only the authority when the pre-release baseline legitimately changes, then run `pnpm --filter @repo/db db:baseline:mirror` and `pnpm --filter @repo/db db:baseline:check`.
- Never edit the mirror directly or add another active SQL file.
- Verify schema changes with `pnpm --filter @repo/db db:fresh:verify`; use `pnpm --filter @repo/db db:reset:mvp` only for the guarded repository-managed local reset.
- Treat archives and the migration lock as immutable evidence; do not read, edit, or use them in active tooling.

## Avoid

- Adding active historical, forward, backfill, or upgrade SQL.
- Mixing product logic into migration files.
- Changing the authority without regenerating and checking its mirror.
