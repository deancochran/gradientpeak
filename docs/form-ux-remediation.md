## Goal

Make common actions easy on web and mobile without inventing another form system: fewer unnecessary fields, semantic inputs instead of generic text boxes, reversible optional values, clear validation, and reliable saving.

Improve existing `@repo/ui` controls first, then adopt them in real form owners. Do not mechanically add dropdowns, sliders, or presets everywhere. A form that already meets the standards does not need superficial changes.

## Shared standards

1. **Choose the control for the value.** Enums use a select or a small segmented control; dates/timezones use semantic selection; planned durations use units and useful shortcuts; exact targets retain precise entry. Avoid raw URLs/IDs where an existing resource picker is available.
2. **Do not manufacture observations.** Actual duration, distance, RPE and other reported values start unset unless real data exists. Blank is not zero. Planned-duration shortcuts are not defaults for recording actual training.
3. **Keep typed values honest.** Invalid text stays visible and prevents submission; do not silently clamp a typed value into another dose. Bounded slider/stepper choices may intentionally constrain selection. Shared `FormNumberField` supports `clampOnBlur={false}` for non-lossy entry; existing callers require deliberate review before changing their behavior.
4. **Make optional content reversible.** Collapse infrequent settings rather than crowd the primary task. Existing populated fields remain discoverable. Hiding a field must not clear it. Provide a compact clear/unset action where the contract allows null.
5. **Use one primary action.** Simple mobile screens use the existing header action. Sheets/review flows may keep sticky actions. Avoid duplicate header/footer Save controls. Web forms should have semantic submission and predictable Enter behavior.
6. **Preserve work.** Cancel/navigation needs the appropriate dirty guard. Validation, upload failure, stale revision and network errors retain drafts. Confirmed success must not clear text typed after the submitted snapshot.
7. **Respect uncertain writes.** Disable conflicting actions while pending; retain operation identity where the API supports it. Do not claim idempotent retry for an endpoint without that contract. Authentication and recovery retain their non-enumerating response behavior.
8. **Make errors usable.** Associate field labels and messages, announce failures, and focus the first invalid field where supported. Root errors remain visible near the action. Do not rely only on a toast, disabled button, color, or blocking alert.
9. **Use a quiet layout.** One meaningful parent surface, light child sections, no repeated Type/Value labels or card-inside-card wrappers. Reuse theme tokens and support both themes. A screenshot is inspiration, not permission to change data semantics.
10. **Verify the real owner.** Trace callers before improving a legacy component. Shared-control tests prove that control, not every consuming screen. Exercise create/edit, existing values, clearing, invalid input, pending/failure and cancellation at the adopting screen.
